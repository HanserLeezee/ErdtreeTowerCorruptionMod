# 问号房 NPC 加载

九种事件共用 `scene-assets/event-hosts.txt` 定义人物、实体编号和独立显示旗标。

旧实体编号 `45016000..45016008` 存在两处问题：

- 原先以 `entity + 70` 推导的显示旗标属于未分配的 `45016` 组，写入不生效。
- 只改旗标后，现场诊断确认事件已执行启用指令，但 NPC 仍为 `Unloaded`。实体编号的地图内偏移为 `6000..6008`；项目参考的 SoulsRandomizers `EnemyRandomizer.newEntity()` 在法环模式会跳过 `4000..9999`。

实体改为 `45011820..45011828`，显示旗标保持 `45011840..45011848`。地图实体、事件编号、构造器调用和角色控制指令必须同步修改。`event-host-entity-patch` 对现有资源执行迁移，并验证编号冲突、序列化、重复迁移和无关数据不变。

原生回归检查同时约束实体编号范围及可用旗标组；资源校验通过后仍需实机确认 `Map-native service NPC bound`，不能用显示旗标为真代替 NPC 加载成功。

姓名通过独立的 `NpcParam` 行 `95016000..95016008` 绑定表格第六列的原版 `NpcName` 文本编号。这些只是参数行号，实体仍使用 `45011820..45011828`。各行复制原服务 NPC 参数，仅修改 `nameId`，避免九种外形都显示罗德莉卡。`event-host-name-patch` 同步生成参数与地图，并验证其他 NPC 和行为字段不变；运行时进入事件房前校验配套姓名参数。

2026-11-01 实机复验：PID 26728 继续原第 16 节点，`45011821` 加载状态为 `ReadyForActivation`，其余八名 NPC 为 `Unloaded`。日志记录事件房绑定成功、`Native NPC interaction: service=6`，随后事件战斗生成两名敌人。此次验证为无缝启动、未组队；其余事件角色及双机尚未逐项实测。
