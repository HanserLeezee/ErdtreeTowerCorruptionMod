# Seamless 2.0.2 复活接口核对

目标 DLL SHA256：`0a093d8490967bf19c62f895fdf1fda21840282d2b2b371b9b4fc24a0cfe146e`。
对照 2.0.1：`fcd11a1849fd37851bb449be30f1525cf498f63fd1fa568c4e15030ebe7cb251`。

PE 时间戳／SizeOfImage：2.0.2 为 `0x6ae0ad1a / 0xd65000`。以下都是相对模块基址的 RVA，不能用于其他构建。

| 项目 | 2.0.1 | 2.0.2 |
|---|---|---|
| 观战处理函数 | `d7bb0` | `da3c0` |
| 本地复活请求 | `d7ec0` | `da6d0` |
| 状态回调 0/1/2 | `d7fd0 / d8180 / d81f0` | `da7e0 / da990 / daa00` |
| 根指针全局位置 | `222030` | `224030` |
| 根指针写入指令 | `32c09` | `33049` |

对五个函数按 PE 异常表边界反汇编，仅归一化 RIP 相对地址和分支目标后，指令序列完全相同。运行时仍校验未归一化的函数哈希，不进行模糊地址匹配。

2.0.2 初始化器 `0x33049` 把 `rbp+0x3690` 写入根指针。`0x36185` 起初始化观战对象 `rbp+0x2b70`，所以根指针减 `0xb20` 得到对象。对象引用：`+8 -> rbp+0x11b0`、`+20 -> rbp+0x1e40`、`+30 -> rbp+0x2f30`、`+38 -> rbp+0x2a90`。相对差值依次是 `-19c0 / -d30 / +3c0 / -e0`。该初始化片段另有完整字节哈希校验。

请求仍为 `request(object, true, false)`，最后一个参数保持本地请求。仍须核验对象关联的 WorldChrMan、回调树和角色身份；退出观战、原地图原位置、角色存活同时确认后才允许推进结算。30 秒未确认会记录超时，不伪造复活。

测试覆盖两版布局、世界对象不匹配、环形／损坏回调树、混用版本，以及真实 DLL 字节被修改后拒绝校验。真实文件测试需设置 `ERDTREE_REVIVAL_DLL_201` 和 `ERDTREE_REVIVAL_DLL_202`，运行忽略项 `real_dll_signatures_match_both_versions_and_reject_modified_code`。

静态与单元测试不等于双客户端死亡—观战—胜利复活验证。实机日志应依次出现 `Seamless 2.0.2` 接口就绪、`native request submitted`、`native exit confirmed`。
