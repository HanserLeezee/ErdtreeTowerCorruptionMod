# 精简包构建

完整包仍是默认方式。增加 `--slim-game <Game目录>` 可构建精简包；本地试包不要使用 `--upload`。

`SceneBuilder <Game目录> <补丁输出目录> <scene-assets目录> slim-assets` 生成高清公共贴图和公共特效两个资源包的补丁。构建器会使用独立目录实际重建两个文件，核对发布文件的 SHA-256 后才从发行暂存目录移除完整副本。精简包同时排除 `menu/low/01_common.tpf.dcx` 与对应 `.sblytbnd.dcx`，不生成低清补丁。源仓库资源不删除。

依据已验证的 Windows 游戏 2.7.2.0（SHA-256 `f9118fea2cfd8fa3901e8060bfadb1552cb2471771ded8a5b662c4e298ffb328`）：`01_Common` 资源描述符位于 RVA `0x2BC0900`，Hi 标记为 1；贴图加载代码在 RVA `0xD7ABA1`、布局加载代码在 RVA `0xD7A7CC` 均传入固定 `Hi/` 字符串。这两条路径没有随画质或分辨率切换 Low 的分支。此结论不外推到其他游戏版本，省略 Low 后的游戏画面仍需实测。

补丁基于当前验证过的游戏资源和游戏自带的 Oodle 2.6；游戏目录只读，原版资源及 Oodle DLL 均不随精简包分发。原始压缩档案、补丁、解压后结果和最终 DCX 均有哈希校验。不会自动适配未验证的游戏版本。

玩家首次启动需要生成资源，可能耗时数分钟并占用较多内存；以后只校验哈希。`Start-Solo.cmd`、`Start-Seamless.cmd`、两个 PowerShell 入口和启动器共用生成器。`CheckOnly` 不生成文件。保留完整包供不希望等待生成或资源版本不匹配的玩家使用。

生成文件不进入下载清单，补丁、生成器和启动脚本仍走现有事务更新和修复。完整包升级到精简包时旧清单中的大文件会被移除，在下一次启动重建；精简包回到完整包时正常下载完整资源并删除补丁清单。`asset-mode.txt` 明确区分两种包，新的完整包覆盖精简包时不会调用残留补丁。生成失败会阻止启动，下一次启动重新校验；所有输出通过校验前不替换已有资源。旧版完整包没有模式标记，回退旧版时请用新目录。

`distribution/AssetRestore` 使用已有 .NET Framework 4.8，不需要玩家安装新的 .NET 运行库。Oodle 参数及 DCX 格式依据仓库现有 SoulsFormats 实现，生成器只支持已验证的 KRAK level 6。

## 原版物品图标

`SlimIcons` 读取本机原版公共布局，定位生成后的高清 TPF 内的 BC7 图集。只对 160×160、4 像素对齐且解码结果与源 `.rgba` 逐字节一致的图标生成提取索引；自制图标（990000 起）及任何不匹配图标继续分发原文件。当前验证匹配 1690 张，保留 31 张自制图标。

索引保存在资源清单 `Icons` 字段，只包含 ID、图集块偏移、行跨度和像素 SHA-256。启动前先确保高清资源正确，再按缺失／损坏名单生成图标。每张图标经过范围检查、解码、哈希校验后原子替换，失败阻止启动，下次可以继续补齐。`CheckOnly` 接受有效清单承诺生成的图标，但仍要求生成器和解码 DLL 存在；不在清单中的图标必须已有文件。

运行时从已经重建的 `menu/hi/01_common.tpf.dcx` 读取图集；该文件的原版来源在当前支持的游戏版本为 `Data0.bdt`。图标步骤不读取 DLC 归档，不检查 DLC 授权，也不改变游戏内容开关。基本版仍需与当前模组支持的游戏资源版本一致。

BC7 解码使用固定版本 bcdec（MIT），来源见 `distribution/AssetRestore/native/README.md`，许可证随包提供。打包机需要 Visual C++ x64 工具链来构建小型 `Tower.IconCodec.dll`，玩家无需新运行库。构建器会在隔离目录实际提取、核对每张图标，全部通过后才从发行暂存目录移除对应 `.rgba`；源仓库图标保留。
