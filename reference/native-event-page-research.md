# ERNativeUI 事件页面入口调查

核对版本：官方 ERNativeUI-v1.3.0。目标：月光泉 NPC 交互直接进入独立原生页面，三个选项回满生命、回满专注、领取 800 卢恩；不修改事件收益或联机结算规则。

## 已确认

- `docs/guides/menus-and-pages.md`：页面结构、标题、说明及按钮在提交注册后不可变；没有公开的运行时独立页面打开接口。
- `src/native_menu.cpp` 的 `SubmenuButtonThunk` 持有原生父页面指针，通过 `request_navigate_page(&parent_page, target, submenu)` 打开子页。
- `src/hooks.cpp:2859` 的 `request_navigate_page` 显式拒绝空父页面，检查模态窗口所有权，并用 `g_submenu_navigation` 维护父子页面关系。不能直接把 NPC TalkScript 指针当父页面。
- 同一函数的 Previous 分支调用原生 Back 后恢复仍存活的父页面；页面销毁、输入锁与返回栈必须配对。关闭 NPC 对话后沿用旧设置页地址不是可靠方案。
- 官方 `docs/features.md` 把赐福入口、复用其他游戏页面模板和运行时加载自定义 GFX 列为未来研究，并明确尚无受支持的挂钩路径。

## 爬塔已有接入点

- `native/src/native_talk.rs`：`EventMenu.recovery`、`EventRequest::Recovery(usize)`，现有对话状态机负责交互和关闭。
- `native/src/rooms.rs`：当前房间向 NPC 提供事件状态，取得一次性交互请求。
- `native/src/runtime.rs`：月光泉请求消费与结算；保留在游戏任务线程完成，不从 ERNativeUI worker 直接扣款、发奖励或改本局状态。

## 最小原型需要先补的边界

1. 当前游戏 2.7.2.0 的原生设置根页面创建、激活和退出入口；现有官方笔记中的参考 RVA 不直接套用。
2. 将事件打开请求排入正确的 UI 线程，创建独立根页面并可靠持有其生命周期，然后才能复用现有子页控件。
3. 绑定会话标识（本局、节点、事件、玩家）。选项只排队一次，回到游戏线程后再次验证房间、角色存活、事件未消费、联机权限。
4. 退出、传送、死亡、断线后撤销待处理请求，解除输入锁并销毁页面；不留下设置页返回栈。
5. 月光泉三个静态按钮足以验证入口。动态价格、武器名称、词条对照和美术布局是之后的独立工作，不以“注册成功”代替实测。

## 验证要求

先验证打开、返回、重复打开、传送中取消；再验证三个选项各只结算一次；最后验证房主与客机。未验证独立根页面生命周期前，不把内部函数调用加入正式 DLL。

本次仅完成官方源码和项目调用链调查，未安装事件页面，也未更换框架主机。原生按键页与现有事件仍保持当前实现。

## 只读生命周期观测

`distribution/menu_lifecycle_probe.py` 验证游戏 SHA256 后，以 PROCESS_VM_READ／PROCESS_QUERY_INFORMATION 读取进程，通过 RTTI 定位 CSMenuMan；记录 0x90 的 UI 状态数组、0x80 的 CSPopupMenu、0x88 的 MenuWindowJob。最多运行 300 秒，只记录变化，不写内存、不安装挂钩、不调用游戏函数。状态数组解码的两项测试通过。

2026-11-02 本机已定位当前版本 CSMenuMan 全局指针 RVA `0x3D72840`，观察到 CSPopupMenu 与 MenuWindowJob 的正确 RTTI。该 RVA 只是只读观测结果，不是可调用的页面入口。接下来通过玩家操作系统菜单、爬塔子页和返回，记录生命周期；这仍不能替代页面构造函数及所有权的验证。

19:38 的第二次采样捕捉到 6 个状态快照：槽 0 隐藏后槽 37 显示，随后槽 37 隐藏、消失，槽 0 恢复显示。CSMenuMan、CSPopupMenu、MenuWindowJob 地址全程不变。玩家确认已完成系统菜单、爬塔子页与返回操作，但这些外层状态无法区分根页与子页；不能据此认定已验证子页销毁或独立构造。下一步使用官方 EnableDiagnostics，在现有已验证挂钩内记录 parentPage、boundNativePage、subHandler 以及返回路径，不额外植入猜测的函数调用。诊断仅用于一次测试，结束后恢复关闭。

## 19:45 官方详细诊断结果

完整记录保存在本聊天工作目录 `work/ernativeui/page-diagnostic-completed.log`；静态反汇编保存在 `work/ernativeui/open-subpage-272.asm`。以下地址来自 SHA256 已核对的当前 2.7.2 游戏，不沿用旧版参考 RVA。

- 游戏选项父页面：`00007FF1DB91E000`；爬塔子页：`00007FF1DCBC6000`，为不同对象。
- 19:45:25.691 请求打开子页，函数返回时 `boundNativePage=0`；19:45:25.724–.725 才构建子页，约 33 毫秒后成功加入 5 个控件，`faulted=0`。
- `openSubPage` RVA `0x950D00`，子页处理器 RVA `0x95BC20`，游戏选项处理器 RVA `0x95A2A0`，原生 Back RVA `0x748180`。这些是定位锚点，不表示允许脱离框架直接调用。
- 当前文件的 `0x950D00` 反汇编确认：读取传入指针槽中的父页面；后续读取父页面 `+0x1CE2`，并引用 `+0x50` 作为后续调用参数。因此传空父页或伪造只有 vtable 的壳对象不成立。
- 普通取消/返回未产生销毁记录。玩家已完成返回，但不能从日志证明子页释放时机，也不能将旧父页地址保留到下次 NPC 交互。

阶段结论：已验证标准设置菜单中的异步子页构建；尚未验证独立根页面的构造、退出和所有权，不安装 NPC 开页试验调用。下一步应离线追踪上述父页面上下文和页面任务构造，暂不要求玩家重复相同操作。安装目录的 `EnableDiagnostics` 已恢复 0，仅当前进程保留已加载的诊断设置。

## 离线工厂与析构调查

可复现工具：`distribution/native_page_audit.py --exe <eldenring.exe> --out <审计目录>`。工具校验完整 SHA256，只读磁盘文件，不访问游戏进程。直接解析异常目录的 235897 个条目，避免 pefile 默认解析结果仅含 11495 条导致遗漏边界。两项边界测试通过。本轮输出在聊天目录 `work/ernativeui/page-audit-272/`，包含 36 个函数反汇编与 32 条经过指令边界验证的直接调用。

确认的当前版本路径：

| RVA | 静态证据及意义 |
| --- | --- |
| `0x950D00` | 完整范围到 `0x951018`；之前导出的固定 0x300 字节片段少了末尾。最终向父页 `+0x10` 调用 `0x7AA580`，不是同步返回新页面。 |
| `0x808D10` | 构造包含 `0x808E40` 回调的任务组合，通过 `0x809960` 包装。 |
| `0x808E40` | 传入子页初始处理器和 `0x95BC20` 控件处理器，调用通用工厂 `0x9601E0`。 |
| `0x9601E0` | 按页面类别选择资源，分配 0x1DA8 字节，调用 `0x94DBC0`，随后通过 `0x958290` 配置处理器。 |
| `0x94DBC0` | 写入 RVA `0x2B16978` 的 vtable，其 RTTI 明确为 `CS::OptionSettingDialog`。构造基类、持有上下文并初始化三个函数对象槽；不是无依赖的 POD 初始化。 |
| `0x9539D0` | 上述 vtable 槽 1 指向此函数；调用 `0x94EC40` 后按标志释放 0x1DA8 字节，符合 deleting-destructor 包装。定位此函数不代表可以手动销毁仍被菜单持有的对象。 |
| `0x93DBE0` | 当前版本系统设置分类工厂。读取传入上下文 `+8` 和 `+0x100`，根据类别调用多个页面包装函数，不能用 CSMenuMan 单例直接替代该上下文。 |
| `0x93CDB0` | 分类切换入口：上下文 `+0x68` 是十项页面缓存，`+0xB8` 是当前页面；仅缓存缺失才调用 `0x93DBE0`，随后同步页面状态、切换可见性。再次说明工厂应由容器管理，不能脱离容器只分配页面。 |
| `0x94EC40` | 析构清理三个函数对象槽，销毁 `+0x1B38` 成员，再跳转到基类清理 `0x91E4C0`。直接 free 会跳过这些对象清理。 |
| `0x748180` | Back 包装向事件路径提交对象，并设置页面 `+0x3B0` 防重复标记；不是直接释放页面。 |

仍缺的实施前提：独立系统菜单上下文的合法创建与所有权、进入游戏 UI 调度队列的契约，以及页面退栈后回收时序。现有数据足以定位工厂和析构，但不足以编写 NPC 独立开页调用。未修改运行中的 DLL，未调用上述候选地址。

## 月光泉页面预览

已使用公开 API 实现可浏览的月光泉原生子页：三个带叙事名称的按钮、收益及限制说明、居中确认弹窗、确认后的结果预览。使用异步弹窗回调及 pending 门禁，取消／失败时释放门禁，避免重复排队。所有预览结果明确说明未修改角色和事件；不接任何结算函数。

开发入口仅在主 DLL 目录存在 `tower-native-ui-preview.enable` 时注册：系统 → 游戏选项 → 黄金树爬塔 → 事件页面预览（开发）→ 月光泉。删除标记并重启即隐藏，不向普通包默认展示。桥接 DLL 的 v3 ABI 不变。

该阶段验证页面本身与交互；NPC 独立入口仍未完成，不能把预览视为正式事件页接入。当前原型编译通过，实际排版、确认及返回仍需游戏内检查。

骰子赌徒预览已加入同一开发入口：1000／3000 两档赌注，明确展示返还总额、净收益及失败损失，原生确认后交替展示获胜与失败样式（不是本局真实结果）。取消不推进预览结果。与月光泉共用模态排队门禁，不读取当前节点种子、不扣款、不发奖、不标记事件已消费。金额依据 `src/events.rs::DICE_STAKES` 和 `resolve_story` 核对；现行正式赌博事件仍仅单人使用，预览不表示新增联机支持。
